# WWW: World Wide Web
---
### Что такое Интернет?
- Компьютеры обмениваются данными, используя **Интернет-протокол (IP)**
- **IP-адрес** – уникальный идентификатор компьютера:
  - IPv4: 4 байта (например, `10.254.69.23`)
  - IPv6: 16 байт
- **Локальный IP-адрес** – адрес компьютера в локальной сети (например, `192.168.1.5`)
- **Глобальный IP-адрес** – адрес компьютера для выхода в глобальную сеть
- Команда `ipconfig` (или `ifconfig`) покажет локальный адрес
- Обращение к `www.whatismyip.com` покажет глобальный адрес
> 💡 **Важно (NAT):** Локальные адреса не маршрутизируются в интернете. Ваш домашний роутер использует технологию **NAT** (трансляция адресов): он подменяет ваш локальный IP на свой глобальный при отправке данных в сеть.

---
### Интернет как инфраструктура
- **Интернет** — это глобальная компьютерная сеть, объединяющая сотни миллионов компьютеров в общее информационное пространство.
- Интернет представляет свою инфраструктуру для прикладных сервисов различного назначения.
- Самый популярный прикладной сервис Интернета — **Всемирная Паутина (World Wide Web — www)**.

### Символьные имена (DNS)
- Запоминать IP-адреса неудобно. Для этого служит **Domain Name System (DNS)** — сеть серверов с таблицами соответствия символьных имен IP-адресам.
  - `wikipedia.org` → `208.80.152.2`
  - `sites.google.com` → `209.85.227.113`
- **Локальные DNS** — соответствия имен адресам в пределах одной ОС.
  - В Windows таблица хранится в файле: `C:\Windows\system32\drivers\etc\hosts`

### World Wide Web (WWW)
- **WWW** (web, веб, Всемирная Паутина) — распределенная информационная система, предоставляющая доступ к гипертекстовым документам по протоколу HTTP.
- WWW — сетевая технология прикладного уровня стека TCP/IP.
- Построена на **клиент-серверной архитектуре** и использует инфраструктуру Интернет для взаимодействия между сервером и клиентом.

### Архитектура веб-сервиса
Основные компоненты (определяющие www.w3.org):
- **URI / URL** — способы идентификации и адресации ресурсов.
  - *URI* (Идентификатор) — общее имя ресурса.
  - *URL* (Локатор) — подмножество URI, указывающее *где* и *как* его достать (в вебе мы работаем почти исключительно с URL).
- **HTML** — язык гипертекстовой разметки веб-документов.
- **HTTP** — протокол передачи гипертекста.
- **Серверные расширения** (CGI, серверные языки программирования и т.д.).

### URL (Унифицированный локатор ресурсов)
- **URL (RFC 1738)** — стандартизированный способ записи адреса ресурса в www и сети Интернет.
- Имеет гибкую и расширяемую структуру.
- Для записи адреса используется ограниченный набор символов ASCII.

![Анатомия URL](https://commons.wikimedia.org/wiki/Special:FilePath/URL_structure.jpg)

### Структура URL
Общий вид адреса:
`<схема>://<логин>:<пароль>@<хост>:<порт>/<полный-путь-к-ресурсу>`

- **схема** — способ обращения к ресурсу (`http`, `ftp`, `mailto`, `file` и т.п.).
- **логин:пароль** — данные для авторизации (необязательно).
- **хост** — доменное имя или IP-адрес сервера.
- **порт** — порт для подключения (если не указан, используется стандартный, например 80 для HTTP).
- **путь** — уточняющая информация о местонахождении ресурса.
---
### Примеры URL
- `http://example.com` — запрос стартовой страницы по умолчанию
- `http://www.example.com/site/map.html` — запрос страницы в указанном каталоге
- `http://example.com:81/script.php` — подключение на нестандартный порт
- `http://example.org/script.php?key=value` — передача параметров скрипту
- `ftp://user:pass@ftp.example.org` — авторизация на FTP-сервере
- `http://192.168.0.1/example/www` — подключение по IP-адресу
- `file:///srv/www/htdocs/index.html` — открытие локального файла

### HTML (HyperText Markup Language)
- Стандартный язык разметки документов во Всемирной паутине.
- Большинство веб-страниц создано при помощи HTML.
- Язык интерпретируется браузером и отображается в удобной для человека форме.
- Изначально создавался как средство **структурирования** документов без их привязки к средствам воспроизведения.
> ⚠️ *Исторически HTML базировался на стандарте SGML, но современный стандарт **HTML5** является полностью самостоятельной спецификацией (Living Standard), не зависящей от SGML.*

### HTTP (HyperText Transfer Protocol)
- Протокол передачи гипертекста (базовая версия — HTTP/1.1, современные — HTTP/2, HTTP/3).
- Изначально предназначен для обмена гипертекстовыми документами, сейчас возможности расширены для передачи двоичной информации.
- Типичный **клиент-серверный протокол** (схема «запрос-ответ») в виде ASCII-команд.
- Позволяет указать способ представления ресурса (формат, кодировку, язык), что позволяет обмениваться бинарными данными поверх текстового протокола.

### Статический vs Динамический веб
- **Статический веб:** Сервер просто берет готовый файл `.html` с жесткого диска и отдает его клиенту как есть. Чтобы изменить контент, программист должен вручную открыть файл и поправить код.
- **Динамический веб:** Содержимое страницы генерируется **«на лету»** в момент запроса. Сервер запускает программу, которая собирает HTML из кусочков, подтягивает данные из базы данных, учитывает время суток или профиль пользователя.

*Для реализации динамического веба и нужны серверные расширения.*

---
### Серверные расширения
- Для создания динамических сайтов одного HTTP недостаточно — нужно уметь выполнять код на сервере.
- Существуют различные механизмы доступа к программам на стороне веб-сервера (интерфейсы/модули расширения).
- Эти программы генерируют HTML "на лету" и отдают его веб-серверу, который передает клиенту.
- Исторически первый стандарт — **CGI** (Common Gateway Interface).

### Программное обеспечение: Веб-серверы
- **Веб-сервер** — сетевое приложение, обслуживающее HTTP-запросы от клиентов (браузеров).
- Принимает запросы и возвращает ответы (HTML, изображения, файлы, медиа).
- Лидеры рынка: **Apache**, **Nginx**, **IIS**.
> 💡 **Почему популярен Nginx?** Классический Apache создавал отдельный системный процесс на каждое подключение. Nginx использует *асинхронную, событийно-управляемую архитектуру*, обрабатывая тысячи соединений в одном потоке. *(К этому подходу мы вернемся при изучении Node.js)*.

### Программное обеспечение: Браузеры
- **Браузер (web-browser)** — клиентское приложение для доступа к веб-серверам по протоколу HTTP и просмотра веб-страниц.
- Поддерживает и другие протоколы (например, `ftp`, `file`).
- Первые клиенты были консольными (lynx, w3c, links). Они полезны разработчикам для проверки доступности "глазами" поисковых роботов.
- Исторически первый графический браузер — **NCSA Mosaic** (Марк Андерсен, Эрик Бина). Его открытый код стал основой для многих последующих разработок.
